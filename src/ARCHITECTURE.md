# SVIP 当前架构

## 1. 任务与输出

任务是视频人物重要性排序。

- 输入：一个包含多个人物框随时间变化的视频片段
- 输出：每个人物槽位的重要性对数几率
- 决策规则：具有最高最终对数几率的人物被预测为重要人物

当前模型遵循以下分解：

```text
最终重要性 = 一元先验 + 自适应社会关系细化
```

其中：

- `一元先验` 建模以人物为中心的重要性
- `社会关系细化` 建模基于场景上下文的群体交互效应


## 2. 端到端数据流

### 2.1 原始样本

每个 `.npz` 样本包含：

- `frames`: `(T, H, W, 3)`
- `bboxes`: `(T, N, 4)`
- `person_mask`: `(T, N)`
- `frame_mask`: `(T,)`
- `target_index`: 标量重要人物标签
- `scene_category`: 数据集场景ID

在 `src/data/dataset.py` 中实现。


### 2.2 时间重采样与槽位归一化

当前默认值来自 `src/config.py`：

- 原始视频长度：`120`
- 采样帧数：`32`
- 最大人物槽位：`16`

处理步骤：

1. 使用 `frame_mask` 提取有效帧前缀
2. 将有效前缀均匀重采样到 `32` 帧
3. 将人物槽位截断或填充到 `16`
4. 将边界框归一化到 `[0, 1]`
5. 将无效帧和无效人物槽位置零

训练时增强：

- 水平翻转
- 亮度/对比度/饱和度抖动
- 轻微高斯噪声
- 随机排列人物槽位以避免索引捷径学习


### 2.3 进入模型的批次张量

模型接收：

- `frames`: `(B, 32, 3, H, W)`
- `bboxes`: `(B, 32, 16, 4)`
- `person_mask`: `(B, 32, 16)`
- 可选的 `frame_mask`


## 3. 模型概览

顶层模型是 `src/models/ranker.py::PersonRanker`。

其三个语义部分为：

1. `视觉 + 几何骨干网络`
2. `一元先验分支`
3. `场景条件关系分支`

前向路径为：

```text
帧 + 边界框 + 掩码
  -> 每个有效人物的ROI裁剪
  -> DINOv2人物特征
  -> 边界框几何特征
  -> 融合的每人每帧特征
  -> 一元先验分支
  -> 场景上下文分支
  -> 关系分支
  -> 自适应融合
  -> 最终人物对数几率
```


## 4. ROI视觉骨干网络

实现在：

- `src/models/roi.py`
- `src/models/vision_encoder.py`

### 4.1 ROI提取

对于每个有效的 `(batch, frame, person)` 条目：

- 从帧中裁剪人物区域
- 调整大小到 `196 x 196`
- 使用可微分ROI提取

只裁剪和编码有效的边界框。

### 4.2 视觉编码器

骨干网络：

- 离线 `DINOv2-Base`
- CLS令牌输出
- 输出维度：`768`

实现细节：

- 使用骨干网络均值/标准差归一化图像
- 运行transformer骨干网络
- 取CLS令牌
- 如果输出维度不同，可选投影
- L2归一化最终特征

当前微调策略：

- 热身第1轮：冻结骨干网络
- 后续轮次：解冻最后 `1` 个transformer块，使用 `attn_ln` 模式
- `attn_ln` 表示只有注意力相关和归一化参数可训练


## 5. 几何编码器

实现在 `src/models/bbox_geom.py`。

每个人物框的输入：

- `x1, y1, x2, y2`
- `cx, cy`
- `w, h`
- `area`

所以原始几何向量是 `9` 维的。

当前几何MLP：

- `Linear(9 -> 64)`
- `ReLU`
- `Linear(64 -> 64)`
- `LayerNorm(64)`

输出：

- `geom_feats`: `(B, 32, 16, 64)`

重要设计选择：

- 几何是主要融合特征路径的一部分
- 但也通过显式先验在一元先验中单独重用


## 6. 每帧特征融合

实现在 `src/models/ranker.py`。

融合的输入：

- 人物ROI视觉特征：`768`
- 几何特征：`64`

连接维度：

- `768 + 64 = 832`

融合MLP：

- `Linear(832 -> 768)`
- `LayerNorm(768)`
- `GELU`
- `Dropout(0.10)`

输出：

- `fused`: `(B, 32, 16, 768)`

这个融合特征是共享的骨干表示，用于一元和关系建模。


## 7. 一元先验分支

实现在 `src/models/intrinsic.py`。

这个分支回答：

```text
仅从人物局部证据来看，这个人物看起来有多重要？
```

### 7.1 输入

一元先验使用：

- 共享融合特征 `(B, 32, 16, 768)`
- 归一化边界框 `(B, 32, 16, 4)`
- 人物掩码

### 7.2 时间投影

首先投影每帧融合特征：

- `LayerNorm(768)`
- `Linear(768 -> 256)`
- `GELU`
- `Dropout(0.20)`

这给出每帧大小为 `256` 的一元隐藏特征。

### 7.3 三个时间池化候选

对于每个人物，模型计算三个一元摘要：

1. `mean_pool`
2. `max_pool`
3. `attention_pool`

注意力池化使用：

- `Linear(256 -> 128)`
- `GELU`
- `Linear(128 -> 1)`

然后一个小的选择器决定如何组合这三个池化。

池化选择器：

- 输入：`mean_pool + 显式先验`
- `LayerNorm(256 + prior_dim)`
- `Linear(... -> 128)`
- `GELU`
- `Linear(128 -> 3)`
- `softmax`

最终池化的一元特征是均值/最大/注意力池化的加权混合。

### 7.4 显式一元先验

一元分支还使用手工制作的可解释先验。

静态先验：

- 可见比例
- 面积均值
- 面积最大值
- 中心偏置均值
- 中心偏置最大值
- 高度均值

运动先验：

- 中心运动均值
- 中心运动最大值
- 面积变化均值
- 特征变化均值

所以当几何和运动先验都启用时，先验维度是 `10`。

### 7.5 一元编码器和评分器

一元编码器：

- `LayerNorm(256 + prior_dim)`
- `Linear(... -> 256)`
- `GELU`
- `Dropout`
- `Linear(256 -> 256)`
- `LayerNorm(256)`
- `GELU`

一元评分头：

- `Dropout`
- `Linear(256 -> 1)`

输出：

- `intrinsic_logits`: `(B, 16)`
- `intrinsic_features`: `(B, 16, 256)`


## 8. 场景上下文分支

实现在 `src/models/scene_prior.py`。

这个分支回答：

```text
应该调节关系解释的场景上下文是什么？
```

重要语义点：

- 场景被视为潜在的客观上下文
- 它本身不是决策者
- 它调节关系线索如何被解释

### 8.1 关键帧采样

从 `32` 个采样帧中，均匀选择 `8` 个关键帧。

### 8.2 全帧场景编码

对于每个关键帧：

- 在 `no_grad` 下将整个帧送入共享的DINO骨干网络
- 取 `768` 维的CLS令牌

投影关键帧令牌：

- `Linear(768 -> 256)`

### 8.3 场景transformer编码器

当前场景编码器：

- `1` 个TransformerEncoder层
- 隐藏维度 `256`
- `4` 个头
- FFN维度 `512`
- GELU激活

它还使用学习到的关键帧时间位置嵌入。

### 8.4 场景池化与原型混合

然后：

- 一个学习到的场景查询执行 `MultiheadAttention`
- 获得池化的场景种子
- 场景种子与 `8` 个可学习的场景原型匹配
- 原型混合被加到池化的种子上
- 最终的 `LayerNorm(256)` 给出场景令牌

输出：

- `scene_token`: `(B, 256)`
- `scene_logits`: `(B, 8)` 原型分配对数几率
- `scene_tokens`: `(B, K, 8)` 关键帧到原型的对数几率

场景只通过原型一致性损失进行弱监督，而不是固定的11类分类。


## 9. 关系分支

实现在 `src/models/relation.py`。

这个分支回答：

```text
一个人物的一元重要性应该被群体交互细化多少？
```

### 9.1 输入与投影

输入：

- 共享融合特征 `(B, 32, 16, 768)`
- 边界框 `(B, 32, 16, 4)`
- 人物掩码
- `scene_token (B, 256)`

第一次投影：

- `Linear(768 -> 512)`

所以关系隐藏大小是 `512`。

### 9.2 SocialMemoryLayer

每一层建模一步场景条件的社会交互加上时间记忆更新。

当前关系深度：

- `2` 层

每个 `SocialMemoryLayer` 有：

- `q_proj: 512 -> 512`
- `k_proj: 512 -> 512`
- `v_proj: 512 -> 512`
- `self_proj: 512 -> 512`
- `scene_q: 256 -> 512`
- `scene_v: 256 -> 512`
- `edge_bias: 6 -> heads` 如果启用空间边缘特征

### 9.3 空间关系构建

在每帧内：

- 在有效人物之间构建人物-人物图
- 使用最近邻稀疏化，`topk = 8`
- 使用成对几何特征：
  - `dx`
  - `dy`
  - `distance`
  - `IoU`
  - `dw - sw`
  - `log area ratio`

这 `6` 个特征调节关系边缘。

注意力式空间交互然后产生：

- 传入消息
- 传出消息
- 4个社会统计量：
  - 传入强度
  - 传出强度
  - 互惠性
  - 焦点性

### 9.4 时间社会记忆

关系层保持每人记忆，使用：

- `GRUCell(512, 512)`

在每一帧：

- 当前交互特征被融合
- GRU更新人物的社会记忆状态

因此当前帧在累积的社会历史背景下被解释。

### 9.5 层更新块

每个层更新使用：

- 连接：
  - 自投影节点特征
  - 传入消息
  - 传出消息
  - 投影的4维社会统计量
  - 场景值
- `LayerNorm(512 * 5)`
- `Linear(2560 -> 512)`
- `GELU`
- `Dropout`
- `GRUCell`
- 残差FFN：
  - `Linear(512 -> 1024)`
  - `GELU`
  - `Dropout`
  - `Linear(1024 -> 512)`

### 9.6 时间池化与关系增量

在所有帧和所有层之后：

- 随时间累积关系状态
- 随时间聚合4维社会统计量
- 每帧与场景令牌连接
- 执行时间注意力池化

时间注意力头：

- `Linear(512 + 4 + 256 -> 256)`
- `GELU`
- `Linear(256 -> 1)`

然后关系增量头：

- `LayerNorm(512 + 4 + 256)`
- `Linear(... -> 512)`
- `GELU`
- `Dropout`
- `Linear(512 -> 1)`

输出：

- `relation_delta`: `(B, 16)`
- `relation_features`: `(B, 16, 512)`


## 10. 自适应融合

实现在 `src/models/ranker.py`。

模型不简单地直接添加一元和关系分数。

而是使用一个门控，条件是：

- 一元特征 `(256)`
- 投影到 `(256)` 的关系特征
- 场景令牌 `(256)`

门控网络：

- 关系门控特征投影：`Linear(512 -> 256)`
- 门控MLP：
  - `LayerNorm(256 + 256 + 256 = 768)`
  - `Linear(768 -> 256)`
  - `GELU`
  - `Dropout`
  - `Linear(256 -> 1)`

门控值：

```text
relation_gate = 1 + 0.25 * tanh(gate_mlp(...))
```

所以它是围绕 `1` 的温和残差调制，而不是硬抑制的sigmoid门控。

当前关系缩放：

- `relation_delta_scale = 0.85`

最终对数几率：

```text
final_logits = intrinsic_logits + relation_gate * 0.85 * relation_delta
```

## 12. 损失设计

实现在 `src/engine/loss.py`。

总损失为：

```text
L = L_importance
  + L_preference
  + L_intrinsic_aux
  + L_relation_aux
  + L_scene_consistency
  + L_cf_relation
  + L_cf_scene
```

### 12.1 主分类损失

- 最终对数几率的交叉熵

### 12.2 偏好损失

- 目标与软负样本聚合的排序式损失
- 通过 `softplus(beta * (neg_soft - pos))` 实现
- 当前 `beta = 1.0`

### 12.3 一元辅助损失

- 直接在一元对数几率上的交叉熵
- 强制一元分支保持清晰的以人物为中心的角色

### 12.4 关系辅助损失

- 直接在关系贡献对数几率上的交叉熵
- 强制关系分支承担自己的判别责任

### 12.5 场景一致性损失

- 来自池化场景令牌的场景原型对数几率定义软目标
- 关键帧级原型对数几率通过KL散度向这个目标正则化
- 一个熵式多样性项避免坍缩到单个原型

### 12.6 反事实间隔损失

对于每个样本，定义排序间隔：

```text
间隔 = 目标对数几率 - 软负样本对数几率
```

然后要求：

- 完整间隔 > 无关系间隔 + 关系间隔阈值
- 完整间隔 > 无场景间隔 + 场景间隔阈值

这鼓励最终预测器真正依赖关系和场景证据。


## 13. 模型为什么预测重要人物

对于一个人物槽位，当以下所有或大部分情况发生时，模型预测高重要性：

1. 人物本身看起来重要
   - 强的外观表示
   - 中心/大/持久的几何先验
   - 强的自身运动或时间显著性

2. 人物在社会上重要
   - 接收强的传入交互
   - 具有焦点群体角色
   - 随时间累积有意义的社会记忆

3. 场景上下文使这些关系线索可解释
   - 关系不是在无场景方式下判断的
   - 场景令牌调节关系细化和融合

4. 即使在反事实移除下，最终间隔仍然强
   - 如果移除关系，性能应该变差
   - 如果移除场景上下文，性能应该变差

## 16. 简短总结

当前实现通过以下链识别重要人物：

1. 采样和归一化视频-人物数据
2. 裁剪每个有效人物ROI
3. 用DINOv2编码每个ROI
4. 用紧凑几何MLP编码每个边界框
5. 将视觉和几何特征融合成共享的每帧人物表示
6. 从池化的人物局部证据构建一元先验
7. 使用轻量级transformer加原型混合从关键帧构建场景令牌
8. 用社会记忆随时间构建场景条件社会关系状态
9. 计算每人关系细化
10. 自适应融合一元先验和关系细化
11. 训练模型使移除关系或场景会损害排序间隔

这是在 `src/` 下实现的精确当前架构，应被视为未来实验的真实来源。
